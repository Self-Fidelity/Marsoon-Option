## 1. 已验证端点清单（全部实测，含返回样例）

所有端点同域前缀：`https://www.barchart.com`，匿名（未登录）状态下即可访问，**在浏览器页面上下文内 fetch**（cookie 同域共享）。

### ① 期货报价 ✅

```
GET /proxies/core-api/v1/quotes/get?symbols=ESU26&fields=symbol,lastPrice,volume,openInterest&raw=1
```

返回：`{"data":[{"symbol":"ESU26","lastPrice":"7,647.00",...,"raw":{"lastPrice":7647}}]}`
→ 喂 **01 总览** 的标的价格、`itm.lastPrice` 基准。

### ② 1分钟K线 ✅（P0-1 缺口已闭合）

两种形态，任选：

```
GET /proxies/timeseries/queryminutes.ashx?symbol=ESU26&interval=1
→ CSV 文本：2026-09-01 00:00,1,7692.75,7692.75,7691.25,7691.25,211
  （时间,?,O,H,L,C,volume），当日约 26KB

GET /proxies/core-api/v1/historical/get?symbol=ESU26&interval=1min&fields=tradeTime,openPrice,highPrice,lowPrice,lastPrice,volume
→ JSON，当日 count=524 根
```

→ 直接闭合 **06 Intraday 面板** 的"简易K线"需求（用户明确不要深度数据）。interval 支持 5/15/60 等。

### ③ 期货期权链（核心突破）✅

```
GET /proxies/core-api/v1/quotes/get?symbol=ESU26&list=futures.options
  &fields=strike,openPrice,highPrice,lowPrice,lastPrice,priceChange,bidPrice,askPrice,volume,openInterest,premium,tradeTime,longSymbol,optionType,symbol
  &groupBy=optionType&orderBy=strike&orderDir=asc&raw=1
```

实测返回：**650 档（325 Call + 325 Put），其中 416 档有持仓量**，单次响应约 150~200KB。
样例（raw 数值）：

```json
{"strike":7400,"bidPrice":23.5,"askPrice":23.75,"lastPrice":23.5,
 "volume":153,"openInterest":9972,"optionType":"Put","symbol":"ESU6|7400P"}
```

关键口径：
- 该 list 返回的是**主力月度到期链**（当前 = 2026-09-16 月度，DTE 15），与官网期权页表格同源。
- **字段必须以 `raw` 子对象为准**：不带 raw 时数值是千分位字符串（`"9,972"`）、结算价带 `s` 后缀（`"26.00s"`）、strike 有格式化错位（`"700.00P"` 实际=7000，以 `raw.strike` 或 symbol 尾部数字为准）。
- `symbol` 格式 `ESU6|7400P`（期货短码|行权价+C/P）。
- **匿名无条数上限**（股票期权匿名 cap 30 条，期货期权链反而全量——已实测）。

→ 喂 **08 GEX 拆分**（per-strike OI/volume）、**01 总览**、**05 热力图**（单到期版）。

### ④ 到期日清单 + 每个到期的 PCR/IV 聚合 ✅

```
GET /proxies/core-api/v1/options-expirations/get?baseSymbol=ESU26
  &fields=expirationDate,expirationType,daysToExpiration,putCallVolumeRatio,putCallOpenInterestRatio,volatility
  &orderBy=expirationDate
```

实测返回 **84 个到期**（weekly+monthly），每条带：
`putCallVolumeRatio`（如 1.35）、`putCallOpenInterestRatio`（如 1.03）、`volatility`（如 "13.28%"）、`daysToExpiration`。
→ 喂 **01 总览 PCR/IV 卡片**、**05 热力图到期维度骨架**、**10 PCR**。
注意：`fields` 参数必填，缺了报 400。

## 3. 抓取策略定案（"代爬 API vs 自写爬虫"的答案）

**GitHub 调研结论：没有现成可用的期货期权链代爬库**（tamnd/barchart-cli 空脚手架；Knuckles-Team/barchart-api 已归档且只有榜单；tke578/barchart 是 2020 年股票包；stubborncake/barchart-uoa 是 UOA 专用）。**→ 自己写采集器，但形态是"浏览器态采集"，不是传统爬虫。**

### 架构：浏览器态采集器 → 本地快照 → 面板消费

```
┌─────────────────────────────────────────────────┐
│  用户本机 Chrome（WebBridge / CDP 持久会话驱动）    │
│  保持 https://www.barchart.com 一个 tab 存活       │
│  ↓ 页面上下文 fetch 同域 proxies 端点（无感过 CF）  │
│  采集器（Node 脚本，按调度发起 evaluate）            │
└──────────────┬──────────────────────────────────┘
               │ POST 快照 JSON（已清洗为内部契约）
               ▼
┌─────────────────────────────────────────────────┐
│  Next.js 后端（Marsoon-Option）                    │
│  POST /api/ingest/barchart  → 校验+清洗+入内存缓存   │
│  GET  /api/snapshot/:panel  → 面板前端轮询/SSE      │
│  Black-76 引擎：由 bid/ask 中价反推 IV → Greeks     │
└─────────────────────────────────────────────────┘
```

为什么是这个形态：
- **Cloudflare 只对真实浏览器放行**（§2 已实测）。WebBridge 驱动用户日常浏览器，天然带 cookie/指纹/登录态，零反爬维护成本——这是路线选择的决定性理由。
- 采集与消费解耦：采集器崩了不影响面板读旧快照；将来切付费源（Databento WS）只换采集器，面板契约不变。

### 频率纪律（重要，别触发风控）

- 数据本身延迟 ≥15 分钟 → **轮询周期定案 15 分钟（`INTERVAL_SEC=900`，2026-09-02 用户确认）**，严禁秒级轮询（无收益、纯风控暴露）。
- K线随链同轮拉取（`queryminutes` 每次返回约 800 根 1min ≈13 小时窗口，15 分钟间隔不会断档）。
- 失败处理：指数退避（1min→2min→5min），连续失败 3 次挂起并上报"抓取失活"状态；单次响应 ~200KB，一天全量 <50MB，存储无压力。
- 页面保活：tab 崩溃/被关 → 采集器自动重开 tab 并恢复调度。

### 合规红线（必须遵守）

- Barchart 免费数据 ToS：**仅限个人研究，禁止商用/再分发**。本看板定位是个人研究工具，OK；任何对外发布必须换付费授权源。
- 延迟数据展示需在 UI 标注"延迟 ≥15 分钟"。
- 正式要 1 分钟实时：切 Databento/MenthorQ（已写入《供应商数据需求.md》，免费源只是开发期与降级兜底方案）。

### 多 serie 架构（v2）

期权页 "Options Type" 下拉就是 serie 清单（无需硬编码，合约滚动自适应）：
下拉 option 的 value 形如 `/futures/quotes/ESU26/options/MV1U26`，第三段即 serie 代码
（月度无第三段，用期货 symbol 本身）。**注意选择器**：Barchart 前端会改版，
旧 class 选择器 `select.bc-options-toolbar__dropdown-type` 已失效，
现按"含 Monthly Options 文本的 option"定位 select。

实测 serie 代码表（2026-09-01，随合约滚动变化）：

| 产品 | 月度 | EOM | 周一 | 周二 | 周三 | 周四 | 周五 |
|---|---|---|---|---|---|---|---|
| ES | ESU26 (650档) | T8U26 (380) | MI6V26 | MV1U26 (736) | MI1U26 (736) | MV6U26 (720) | MW1U26 (722) |
| NQ | NQU26 (450) | MQ6U26 (376) | MC7U26 | MM1U26 (832) | MC1U26 (798) | MM6U26 (742) | MQ1U26 |
| GC | GCZ26 (1788) | —（无 EOM） | IY2U26 | I0AU26 (488) | IY6U26 (480) | I0GU26 (466) | IG1U26 (416) |

serie 到期日推断规则（⚠️ 2026-09-02 复测证伪，详见 §6，P0 改为页面真值）：
- weekly：按星期几在 `options-expirations/get` 清单里匹配最近到期（周二 serie + 今天是周二 → DTE=0，即 0DTE 链）
- monthly：合约月字母→到期月（ESU26→9月、GCZ26→12月）
- eom：合约月内日最大者
- **月码必须取自 serie 期权代码尾部**（`MQ6U26` → U26 → 9月），不能取 serie.futures——期权月≠标的月

**serie 标的期货规则（v2.2 修复，曾致 GC 墙壁错误收敛）**：
- 下拉 URL 路径第二段即该 serie 的标的期货：`/futures/quotes/GCV26/options/I0AU26` → 标的是 **GCV26**（10月），不是主合约 GCZ26（12月）。实测基差：GCZ26 4398.7 / GCV26 4365.5，差 33 点（0.75%）
- 实例：GC 全部周期权挂 GCV26；NQ 9月EOM（MQ6U26）挂 NQZ26；ES 周一周期权挂 ESZ26
- 采集器每轮对**所有涉及的期货合约**取报价（quotes map），引擎按 serie 各自的标的价做 Black-76；regime 判定也在所选 serie 的标的空间
- 修复前症状：GC 0DTE 用 GCZ26（4399）给实际标的 4365 的链定价，墙错误挤在 4400；修复后 CW=4450/PW=4350，与链上 OI 结构一致（4450 call OI 193 / 4350 put OI 207）
- scope=all 聚合时 flip 扫描把候选价按 S×(serieF/主F) 折算到各 serie 空间

**scope 语义（看板顶栏全局总控 收盘/0DTE/30DTE/90D/RTH 五档多选，2026-09-02 周期架构迭代、09-03 十一轮扩档；窗内无周期 chips）**：
- `close` → 收盘固定层（Databento EOD 结算真值，每日一次全天冻结）；本轮留空位，各路由回 has_data:false 空态，不造数
- `0dte` → 当日到期 serie（无则 DTE 最小）——数值口径=当日链；当前为 15min 免费源样本，Databento 接入后升 1min
- `d30` → DTE ≤ 30 的全部 serie 聚合（含 0DTE，嵌套口径 0DTE ⊂ 30DTE ⊂ 90D ⊂ 全部）
- `d90` → DTE ≤ 90 的全部 serie 聚合（含 0DTE），替代旧 `nearest`（已删除）
- `all` → 全 serie 聚合（显示名 `RTH`，key 不变；`combineAnalytics`：跨 serie 同档合并、walls 取极值、flip 按各 serie 自己的 T/IV 重扫净 gamma）
- **heatmap.cells 永远输出全 serie 逐档**（每 serie 一列到期），05 热力图因此多列

**flip 扫描区间陷阱（已修复）**：链档位全跨度 100~10100（含 OI 极小的尘埃档），
用全档位区间扫净 gamma 变号会在无持仓区误捕浮点粉尘（0DTE flip 曾被算到 162.5）。
修复：扫描区间按逐档 |GEX| 累积份额取 0.5%~99.5%（`gexScanRange`）。

## 6. 2026-09-02 复测记录（对照官网逐项实测）

测试方法：WebBridge 直连 barchart 页面上下文，以 serie 页面显示的 "N Days to expiration on MM/DD/YY" 文本为到期日真值。

### 6.1 serie→到期日归属系统性错误（P0，ITERATION.md 任务 1）

`resolveSerieExpiry` 的启发式（weekly 按星期几就近、monthly 按月字母匹配 expirations 清单）在多个 serie 上失效：

| serie | 官网真值（页面原话） | 采集器指派 | 偏差 |
|---|---|---|---|
| ES 月度 ESU26 | 09/17/26（"16 Days to expiration on 09/17/26"） | 09/16 | 1 天（expirations API 把 09/17 标成 weekly，代码偏爱 monthly 类型误选 09/16） |
| ES 周一 MI6V26 | 10/05/26（页面 "Week 1: Oct 2026"） | 09/14 | 3 周（忽略代码月字母 V=10 月） |
| ES 周二 MV1V26 | 10/06/26 | 09/08 | 4 周 |
| GC 周一 IY1V26 | 10 月（V26） | 09/14 | 错列（OI 仅 4） |
| GC 月度 GCZ26 | **11/24/26**（"84 Days to expiration on 11/24/26"；页面月份选择器的 "Dec 2026" 是合约月不是到期月） | 12/16 | 22 天，T 高估 26%；且 11/24 不在 expirations API 返回中 |

修复方向：serie 清单刷新时逐个 navigate serie 页，直接抓页面 "N Days to expiration on MM/DD/YY" 文本作为真值，启发式仅作兜底。

### 6.2 新发现的数据渠道（未用）

- **周期权页 "Week 1~4" 选择器**：每个工作日 serie 暴露 4~5 个符号（例：ES 周一页可选 MI7U26=9/14、MI8U26=9/21、MI9U26=9/28、MI6V26=10/05、MI7V26=10/12）。当前只抓下拉默认指向的 1 个，近期每日到期链大面积缺失。
- **月度页月份选择器**：GC 月度页可选 Oct 2026 ~ Jul 2027 各月；当前只抓默认月，scope=all 缺远端月度。
- **官方 Greeks 字段**：同链端点加 `fields=delta,gamma,theta,vega` 即得，月度 serie 为真值（见 §2 更正）。
