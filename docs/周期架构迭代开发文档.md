# 周期架构（Gamma 周期分层）迭代开发文档

> 创建：2026-09-02
> 范围：**看板级 scope 架构改造**——影响 05/06/08/09/10 等所有消费共享分析层的面板，非单面板迭代
> 背景：gamma 的含义随周期分层（0DTE 日内钉扎 / 90D 波段墙 / 全期限结构仓位 / 收盘仓位真值锚点），看板的周期选择器要从现在的 `0DTE | 近月 | 全部` 升级为四层架构。

## 一、周期档定义（已拍板；2026-09-03 十一轮起五档，见十一节）

| 层 | 按钮 | 聚合范围 | 数据源 | 刷新 | 状态 |
|---|---|---|---|---|---|
| 收盘固定 | `收盘` | 全期限所有 serie | Databento EOD（结算价 + 收盘 OI） | 每天一次，全天冻结 | **本轮搭架构留空位**，Databento 未接入 |
| 0DTE | `0DTE` | 当日到期 serie | Barchart 15min 轮询 | 跟随采集 | 现有能力，**口径标注：当前为免费源 15min 样本，未来接 Databento 后切 1min 采集** |
| 30DTE | `30DTE` | DTE ≤ 30 的全部 serie（**含 0DTE**） | 同上 | 同上 | 十一轮新增（2026-09-03） |
| 90D | `90D` | DTE ≤ 90 的全部 serie（**含 0DTE**，嵌套口径：0DTE ⊂ 30DTE ⊂ 90D ⊂ 全部） | 同上 | OI 每天才变，盘中只是价格重估 | 本轮实装（替代现有"近月"） |
| 全部 | `RTH`（key 仍 `all`） | 所有 serie | 同上 | 同上 | 现有能力；十一轮显示名由"全部"改 `RTH` |

**"收盘固定"与"RTH（全期限盘中）"的关系**：聚合范围相同（全期限），差别在数据时点——收盘固定 = 每天一次的结算真值（仓位锚点，全天不变）；RTH = 盘中 15min 最新价/IV 重估的浮动值。两者偏离本身是交易信号。
**收盘固定层的形态**：五档语境下为第一档（`收盘`），整体切换看板（不叠加参考线；叠加层列入 06 后续计划，见六节）。

## 二、架构改造点

### 1. scope 语义升级（共享分析层 `src/server/barchart-analysis.ts`）

- 现有 scope 枚举 `0dte / nearest / all` 升级为五档 `close / 0dte / d30 / d90 / all`（`nearest` 已由 `d90`/`d30` 替代）。
- **删除 `nearest`（近月），新增 `d90`**：serie 选择从"最近一条"改为"DTE ≤ 90 的全部 serie 聚合"（聚合走现有 `combineAnalytics` 路径，与"全部"同法、只是 serie 子集不同）。
- `close`：数据源未通，本轮 scope 接受该值但返回**空态标记**（`has_data: false` 或等效），所有面板按"无数据不降级"红线显示空态，不报错、不造数。
- 影响面：05/08/09/10/06 全部经共享分析层消费 scope，切换语义随之一致变化，无需逐面板改口径。**05 面板本体不动**（用户既定），只是它显示的"90D"内容随 scope 变化，后续再做期限矩阵对齐（六节）。

### 2. 切换器 UI（BoardView 级）

- 顶部 scope 切换按钮组 `0DTE | 近月 | 全部` → `收盘 | 0DTE | 30DTE | 90D | RTH` 五档多选总控（至少 1 个，[0] 为主周期）。本节为早期设计稿，最终以第十一节多选总控为准。
- `收盘` 档在 Databento 接入前：按钮可选中，各面板显示"收盘数据待接入（Databento EOD）"空态；按钮旁可加小注记。
- `0DTE` 档：按钮 title/图例注记"当前 15min 免费源样本 · Databento 接入后升 1min"。

### 3. 收盘固定层数据落地（未来，先定契约）

- Databento 每日 EOD 拉取 → 结算价 + 收盘 OI 跑一次 `analyzeChain`/`combineAnalytics`（全期限）→ 落盘 `data/eod/YYYY-MM-DD.json`（小文件，全量 walls/flip/每档 greeks）。
- 面板切 `收盘` 档时读该文件，全天不变；文件缺失 → 空态。
- 本轮只定义文件契约与接口注入点，不写 Databento 拉取代码。

### 4. 刷新频率分层（流量优化，二期）

OI 每天只变一次，四层对刷新的需求完全不同：

| 层 | 需求 |
|---|---|
| 收盘 | 每天一次（EOD 拉取） |
| 0DTE | 高频（现 15min，Databento 后 1min） |
| 90D / 全部 | 每天 1~2 次足够（盘中重算只是价格重估） |

二期改造采集器：**0DTE serie 高频抓，其余 serie 每日低频抓**，流量砍掉一大半，与防 ban 目标对齐。本轮不动采集器，仅记录。

## 三、服务器负荷与增量架构（设计约束，所有后续迭代遵守）

核心原则：**原始数据只追加、只读一次；昂贵计算分层缓存；任何请求触发全量重算都是 bug。**

| 负荷点 | 对策 | 本轮做不做 |
|---|---|---|
| jsonl 全文扫描重算（06/10 回放） | **回放游标**：按"日期+产品+scope"记录已处理文件偏移/轮次，新请求只增量处理新行，结果累进缓存；mtime 变化才触发补算 | 本轮做（06 intraday 路由改造） |
| 聚合结果重复计算 | capturedAt 记忆化（已有），扩展到新路由 | 保持 |
| 磁盘增长（~47MB/天） | 日间归档：原始 jsonl 保留 N 天，过期提炼成"每轮 levels 摘要"小文件后压缩/删除 | 数据量涨上来再做，记录备查 |
| Databento 1min 数据（量 ×15） | 原始 tick 不落盘全量，只留 1m bars + 每轮 levels 摘要；EOD 结果落小文件 | 接入时做，记录备查 |
| 并发请求阻塞 | 同 key 请求合并 + 内存缓存 | 本轮顺带（缓存层加 in-flight 去重） |

## 九、故障记录：采集器串页污染（2026-09-03）

**现象**：`scripts/.serie-cache.json` 的 GC 键下全是 NQ 系代码（NQU26/MQ*/MC*/MM*），`data/snapshots/2026-09-03.jsonl` 的 GC 链实为纳指档位；ES/NQ 报"下拉读取失败"。

**根因**：`fetchSerieList` / `scrapeSerieTruth` 在 `wbNavigate` 后直接 evaluate，不校验浏览器实际落点。页面加载失败/过慢时 evaluate 打在上一个产品残留页面的 DOM 上，把别家下拉清单当真。单浏览器会话顺序 navigate ES→NQ→GC，一棒接一棒污染。

**修法**（`scripts/barchart-poller.mjs`）：

1. `wbNavigate` waitMs 12000→20000；navigate 后轮询（5 次 × 2.5s）等落点 URL 含 `/futures/quotes/{futuresSymbol}/options` 且下拉非空，整段最多重试 3 次。
2. `scrapeSerieTruth` 同样加落点校验（href 须含 serie.path），不符返回 null 走启发式兜底。
3. serie 归属纵深防御，命中即抛错、**不写缓存**：
   - 每个下拉项 path 的标的产品根须属于本产品（`SERIE_PATH_ROOTS`；周期权挂对应月份合约而非主力，如 ES 的 MI6V26 挂 ESZ26，故按产品根放行，跨产品残留页根不同可识别）；
   - 代码前缀白名单（`SERIE_CODE_PREFIXES`）。

**坑**：Barchart 的 serie 代码用 CME clearing code，不是 ES/EW/OG 风格。实测全集（2026-09 合约周期）：
ES = ES/T8/MI/MV/MW（+EW/EW1~EW4 预留）；NQ = NQ/MQ/MC/MM（+MNQ 预留）；GC = GC/IG/IY/I0B/I0G（+OG/MGC 预留）。合约滚动换月时若出现新根码，白名单需按当日下拉实测扩充（防御会抛错提示，不会静默污染）。

**处置**：删除污染缓存 + 当日快照（仅 2026-09-03.jsonl），重启采集器后首轮三产品 serie 归属全部正确。

## 十一、新增 30DTE 档 + "全部"更名 RTH（2026-09-03）

**需求口径**：

1. 在 `0dte / d90 / all / close` 之外新增 `d30`（30 天到期口径）：serie 过滤规则照 d90 同法——DTE ≤ 30 的全部 serie 聚合（含 0DTE，嵌套口径 0DTE ⊂ 30DTE ⊂ 90D ⊂ 全部），聚合走 `combineAnalytics` 同一路径，只是 serie 子集不同；`expiration` 置 0、`F` 用主合约现价（与 d90/all 聚合口径一致）。UI 显示名 `30DTE`。
2. 固定优先级改为 `0dte > d30 > d90 > all > close`（`LINE_SCOPE_ORDER`、`SCOPE_MERGE_ORDER`、`OptionsDashboard.SCOPE_ORDER`、panel-wrappers 内联排序同步）。line 窗多选上限 `LINE_SCOPES_MAX = 3` **保持不变**（徽标/回放成本约束不变）；总控仍可全选 5 档，line 窗联动派生按优先级截断到 3（全选时丢 all+close，close 恒空态、all 与 d90 在当前 serie 分布下高度重叠，实际损失可接受）。
3. `all` 的 key 不动（数据/存档/URL 兼容），仅所有用户可见文案 `全部` → `RTH`：总控 chips、窗内 chips、06 徽标前缀（`ALL` → `RTH`，组合前缀如 `0D+RTH·PW`）、06/07/10 线型图例。

**改动文件**：

- `src/api/options.ts`：`OptionScope` 加 `"d30"`（`"close" | "0dte" | "d30" | "d90" | "all"`），注释升五档口径。

- API 路由白名单 `parseScope` 全部加 `d30`：`dashboard` / `levels` / `chain` / `intraday` / `term`（term 的 `inScope` 加 `dte <= 30` 分支）；dashboard local-demo 回退分支 d30 与 d90 同取次近到期（demo 兜底，非真实路径）。

**用户验收点**：

- 总控与窗内 chips 出现五档：`收盘 | 0DTE | 30DTE | 90D | RTH`；点选 30DTE 各面板（01/05/06/07/08/10）出数，与 90D 口径差异符合嵌套预期（当前快照若所有 serie DTE ≤ 30，d30 与 90D/all 读数相同属口径预期，非 bug）。
- 多选优先级：任意组合点选后选中集恒按 0DTE > 30DTE > 90D > RTH > 收盘 排序，主周期（表格读数/迁移线/徽标全套牌）取最高优先级者，与点击顺序无关。
- 06 徽标组合前缀用 `RTH`（如 `0D+RTH·PW`、`30+90+RTH·FLIP`），右轴牌宽不溢出（超宽 textLength 压缩）；图例五档线型样例与图上墙线一致（30DTE 短虚线区分于 90D 点线与 RTH 低密度虚线）。
- URL 深链 `/board?scope=0dte,d30,all` 打开即选中三档；localStorage 旧存档刷新后正常还原，新存档含 d30 亦正常。

**遗留**：

- d30 无需新采集数据：口径是对现有 serie 全集的 DTE ≤ 30 过滤，现有快照立即生效（与 d90 落地时相同）。
- line 窗上限仍为 3：五档时代若用户反馈 3 档叠加不够用，再评估提高 `LINE_SCOPES_MAX`（徽标列宽与回放成本需同步复算）。
- d30 与 0dte 的差异需等快照里出现 1~30 DTE 的非当日 serie 才能实测区分（与 d90 落地时的钝感注记同类，口径预期非 bug）。
