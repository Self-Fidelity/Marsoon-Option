## 一、设计意图（docs 既定，不再变更）

回答两个问题：**价格现在贴着哪堵墙？仓位真变了还是只是成交热闹？**
形态：期货主力合约 K 线主图 + 成交量副图 + 关键位横线叠加 + 关键位日内迁移折线。

## 二、数据基础（Go 接口实测）

### BARS：期货主力 1 分钟 K 线

- 来源：Go `GET /options/underlying-bars?product&underlying&timeframe=60&from&to`（返回 `bars[]{unix,open,high,low,close,volume,final}`）；`/options/intraday` 的 `bars[]` 是同源组合视图。实测 24h@60s 约 146KB。
- 合约：每产品 1 个主力期货（由后端按 `underlying_symbol` 下发，如 NQU26）。**是期货 K 线，不是期权的**；期权没有 K 线，仓位信息由 LEVELS 承担。
- 频率决策：0DTE 快照 **60 秒**、d30/d90/all **300 秒**、close **每日**（2026-09-10 实测）。

### LEVELS：关键位日内轨迹

- 来源：Go `GET /options/levels?product&scope&from&to&timeframe`（`states[]` + `levels[]`）与 `/options/intraday` 的 `levels[]`。
- 口径与 05/08/09 一致：跟随全局顶栏当前主周期（五档 close / 0dte / d30 / d90 / all），由后端聚合口径决定，06 不自造口径。
- 已知口径限制（继承，不处理）：0DTE 的 T 地板近似导致 IV/flip 偏估；历史日期按快照自带日期判定，不用服务器"今天"。
- ⚠️ 24h@300s 的 levels 响应实测 **3.4MB**，是全站最大响应，注意 BFF 超时预算（见 `../frontend/本地侧优化方案.md` L3）。

### 性能与流量

- 大响应的复用靠服务端快照缓存 + 前端脏更新（`/api/options/version` 驱动，版本不变不重复请求），见 `../frontend/本地侧优化方案.md` L1/L4。
- 前端 React Query 缓存沿用现有模式（staleTime 30s）。

## 三、数据 API（已由 Go 提供）

`GET /api/options/intraday?product=ES|NQ|GC&scope=...`（Go `/options/intraday` 的组合视图）：

- 响应结构（契约在 `src/api/options.ts`）：
  - `bars`: `{unix,o,h,l,c,v,final}[]`，升序。
  - `levels`: 每个快照点 `{t, spot, call_wall, put_wall, gamma_flip, atm_iv, expected_move}`（字段为 null 则该点该项缺省，前端断线处理）。
  - `current`: 最新一轮现值（用于横线与读数）。
- 无数据 → `has_data:false` + 空数组，前端显示空态文案，**不展示模拟数据**。

## 四、前端：新建 `IntradayPanel`

`src/features/board/IntradayPanel.tsx`，手写 SVG（项目无图表库，沿用 05/08 面板模式）：

1. **主图：蜡烛图**（新写，SVG rect+line）。**周期切换：1m / 5m / 15m / 30m / 1h 五档**（面板工具行切换，默认 5m）；聚合用通用纯函数 `aggregateBars(bars, minutes)`（OHLC 首末/最高最低、V 求和，按周期起点对齐时间桶），周期做成配置数组，后续扩 2h/4h 只加数组项。数据可行性已核算：单 session 800 根 1m ≈ 13h → 5m≈160、15m≈53、30m≈26、1h≈13 根；拼接全天（~23h）后 30m≈46、1h≈23 根，均可用。聚合本身不会空（有数据即有蜡烛，只是大周期根数少）。最新价横虚线 + 右端价格标签。
2. **副图：成交量柱**（主图下方窄条区域，同色涨跌着色）。
3. **横线叠加**（现值）：CALL WALL（绿）/ PUT WALL（红）/ GAMMA FLIP（品牌色虚线）/ SPOT（亮线）四条，右端数值标签——样式与 09 面板的 LevelLineRow 语义色保持一致。
4. **迁移折线**：flip、call wall、put wall 的日内轨迹（15min 点连线，断点跳过），直接画在主图价格坐标系上，与横线同色但低透明度，可开关（默认开）。可复用/仿写旧看板 `dashboard-panels.tsx:129-150` 的 Sparkline 折线路径生成。
5. 面板右上小工具行：周期切换（1m/5m/15m/30m/1h）、迁移线开关。产品/scope 跟随看板全局上下文（现行方案：`render(panelId)` + zustand `board-window-store`，早期 `BoardPanelContext` 方案已废），不自建切换器。

布局约束：半行宽（w:6 h:14），图区紧凑，坐标轴标签 ≥9px、颜色用 `--ms-*` 变量体系，与 09 第四轮定下的可读性标准一致（不糊、不半透明低对比）。

## 五、开发步骤

1. `src/api/options.ts`：intraday 响应类型契约。
2. `src/app/api/options/intraday/route.ts`：**BFF 代理透传 Go `/options/intraday`**（早期版本在此做本地回放重算，该实现已删除）。
3. `src/features/board/IntradayPanel.tsx`：蜡烛图 + 量柱 + 横线 + 迁移折线 + 工具行。
4. `panel-registry.tsx`：`intraday` 面板 `implemented: true`，render 接 `IntradayPanel`（`render(panelId)` 方案，`BoardPanelContext` 已废）；窗口配置走 `board-window-store`。
5. 验证：`npx tsc --noEmit`；起 dev，核对横线值与 09 面板同 scope 读数一致、bars 时间轴连续、迁移线点数与后端快照数相符。

## 六、明确不做

- 期权 K 线（无数据）、次合约 K 线。
- 60s 粒度 levels（现为后端快照粒度决定，前端不插值）。
- 任何上游请求或轮询频率改动（本仓不再持有采集链路）。
- 跨天历史回看（只画当天；多日期选择器后续再议）。

## 七、风险与注意

- **session 边界**：bars 拼接必须以 unix 去重排序，同日跨 session 的重叠段以较新为准。
- **大响应**：levels 24h@300s 可达 3.4MB，注意 BFF 超时预算（`../frontend/本地侧优化方案.md` L3）。
- **时区判定**：历史点的 0DTE 判定按该点自带时间戳的日期，不用服务器当前日期，否则历史日 flip 会错。
- **levels 轨迹中断**：某点某产品缺失时该点跳过，折线断连，不插值编造。
