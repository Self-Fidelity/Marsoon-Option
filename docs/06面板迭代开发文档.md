## 二、数据基础（已核实，`data/snapshots/2026-09-02.jsonl` 实测）

### BARS：期货主力 1 分钟 K 线

- 来源：采集器 `scripts/barchart-poller.mjs` 每轮抓 `bars1m`（Barchart `queryminutes.ashx`，`BarchartBar1m {unix,o,h,l,c,v}`，保留末尾 800 根）。
- 合约：每产品 1 个主力期货——ES→ESU26、NQ→NQU26、GC→GCZ26（`poller.mjs:37-41` PRODUCTS）。**是期货 K 线，不是期权的**；期权没有 K 线，仓位信息由 LEVELS 承担。
- 质量（当天 48 轮落盘实测）：最后一轮各产品 296 根，05:00–09:55 UTC 连续、无 >1min 空洞、零缺失成交量、无畸形 OHLC。
- **结构性注意**：Barchart 只回当前交易时段的 K 线，session 切换后旧数据从接口消失；但旧轮已落盘，**拼接当天多轮快照的 bars（按 unix 并集去重）即可覆盖完整时段**。

### LEVELS：关键位日内轨迹（离线重算）

- 内存仓 `barchart-store.ts` 只存最新一轮快照 → 日内序列**只能从 jsonl 回放**。
- jsonl 每行含完整原始链，`analyzeChain(chain, F, dte, multiplier)`（`barchart-greeks.ts`）是纯函数 → **逐行回放当天 jsonl，重算每轮的 spot / call_wall / put_wall / gamma_flip / atm_iv / expected_move**，得到 15min 粒度、当天约 48 点的真实轨迹（替代 `/api/options/levels` 现有的"最新值平铺"假历史）。
- 口径与 05/08/09 一致：跟随全局顶栏当前主周期选择（五档 close / 0dte / d30 / d90 / all，nearest 已废除），由共享分析层的 serie 选择语义决定，06 不自造口径。
- 已知口径限制（继承，不处理）：0DTE 的 T=0.35 天近似导致 IV/flip 系统性偏估；回放历史日期的 0DTE 判定以快照自带 `capturedAt` 对应日期为准，不用服务器"今天"。

### 性能与流量

- 单日 jsonl ~47MB/48 行：逐行流式读取，只取目标产品字段；48 轮 × ES 7 serie 的 Black-76 重算为秒级可接受，**按"日期+产品+scope"做服务端缓存**（文件 mtime 失效）。
- 前端 React Query 缓存沿用现有模式（staleTime 30s / refetchInterval 60s）。

## 三、后端：新增历史 API

新增 Route Handler `GET /api/options/intraday?product=ES|NQ|GC[&scope=...]`：

- 读当天 `data/snapshots/YYYY-MM-DD.jsonl`（日期按"快照所在交易日"口径，跟随现有落盘命名规则）。
- 响应结构（契约加在 `src/api/options.ts`）：
  - `bars`: 拼接去重后的 `{unix,o,h,l,c,v}[]`，升序。
  - `levels`: 每轮一个点 `{t, spot, call_wall, put_wall, gamma_flip, atm_iv, expected_move}`（字段为 null 则该点该项缺省，前端断线处理）。
  - `current`: 最新一轮的现值（直接取共享分析层结果，用于横线与读数）。
- 文件缺失/当天无落盘 → 返回空数组 + 标记，前端显示"今日暂无落盘数据"，**不展示模拟数据**（沿用占位原则）。

`src/features/board/IntradayPanel.tsx`，手写 SVG（项目无图表库，沿用 05/08 面板模式）：

## 六、明确不做

- 期权 K 线（无数据）、次合约 K 线（采集器不抓）。
- 60s 粒度 levels（受 15min 采集间隔限制，远期再议）。
- 采集器、轮询频率、抓取字段的任何改动。
- 跨天历史回看（只画当天；jsonl 按天文件，多日期选择器后续再议）。

## 七、风险与注意

- **session 边界**：bars 拼接必须以 unix 去重排序，同日跨 session 的重叠段以较新轮为准。
- **jsonl 体积**：必须流式逐行读，禁止整文件 `JSON.parse`（单日 47MB+）。
- **回放 0DTE 判定**：用该轮快照 `capturedAt` 的日期，不用服务器当前日期，否则历史日 flip 会错。
- **levels 轨迹中断**：某轮某产品缺失（如当天 round 33 ES 缺）时该点跳过，折线断连，不插值编造。

## 十一、迭代执行记录 · 第四轮：工具行改单行、修复控件错位重叠（2026-09-02）

目标：修复截图反馈的"两行浮着 + 周期分段控件/迁移线/重置视野互相压着"错位 BUG，工具行对标成熟行情面板改单行。纯前端 `src/features/board/IntradayPanel.tsx`，接口不动。

### 错位根因

- 工具行容器是 `flex flex-wrap` + 右区 `ml-auto`：面板半行宽（w:6）下读数条 + 控件区总宽超出行宽即整体换行成两行。
- 读数条内部用 `flex items-baseline` 混合四个 span（其中三个 `shrink-0` 不可压缩、仅中间 OHLC 段 `truncate`），`items-baseline` 与右侧按钮的 center 基线不一致；换行后控件区与读数段的收缩/基线规则互相挤压，视觉上出现按钮错位重叠。
- 交互提示"滚轮缩放 · 拖拽平移"是右区第四个 `hidden lg:inline` 子项，进一步加剧宽度竞争。

### 改动点

- **单行 flex 工具行**：容器去掉 `flex-wrap`/`gap-y`，改 `flex items-center gap-2`，`sticky top-0 z-10` 与 `bg-[var(--ms-plot-bg)]` 不透明吸顶保留。
- **读数条**：改为单个 `min-w-0 flex-1 truncate whitespace-nowrap font-mono text-[10px] leading-6` 容器，四段文本改普通 inline span（不再各自 shrink-0），空间不够整体省略号截断——绝不换行、绝不溢出压到控件；内容不变（时间 CT·周期 / O H L C / 涨跌额(%) / V），纯文本无背景框。
- **控件区 `ml-auto shrink-0 items-center gap-1.5`**：周期五档 `ms-control` 分段控件（结构/类名对照 09 面板 OptionsChainPanel 工具行，按钮 h-6）、迁移线开关、重置视野按钮，三者统一 h-6 等高对齐。
- **交互提示移出工具行**：从右区删除；重置视野按钮加 `title="重置视野（图表支持滚轮缩放 · 拖拽平移）"`，图例行右端小字同时补"滚轮缩放 · 拖拽平移"。

### 验证结果

- `npx tsc --noEmit` 通过。
- 工具行内已无任何 absolute/负 margin/flex-wrap；半行宽下读数条 truncate 兜底，周期按钮保持 h-6 px-1.5 text-[10px] 无需再降。

## 十三、迭代执行记录 · 第六轮：修复十字光标竖线偏移、读数条定宽防抖动（2026-09-02）

目标：修复用户实拍反馈的两个 bug——十字光标竖线偏离鼠标实际 x、OHLCV 读数条随数字位数变化整行抖动。纯前端 `src/features/board/IntradayPanel.tsx`，接口不动。

### Bug 1 根因与修法

- **真实根因**：`onMouseMove` 用时槽反推吸附索引 `vStart + floor((t-t0)/intervalSec)`。该公式假设 agg 蜡烛时间连续无缺洞，但采集回放数据存在缺分钟（聚合后 agg 有洞），此时"槽索引 ≠ 数组下标"，竖线吸附到槽索引对应的数组元素上，偏离鼠标下的实际蜡烛一根甚至多根。并非 preserveAspectRatio/letterbox 问题（svg `w-full h-auto` + viewBox 纵横比一致，无黑边），也不是 PAD_L/PAD_R 改动残留（换算统一走 PLOT_W）。
- **修法**：改为按 px 直接扫描可视窗口 slice，找蜡烛中心 x 最近的一根吸附（`best` 线性扫描，`hover.cx` 取该蜡烛中心），保证竖线吸附的蜡烛与鼠标下的蜡烛严格一致；右轴价格小牌、横线沿用同一 py 换算不受影响。同时 svg 显式加 `preserveAspectRatio="none"`，消除任何未来 CSS 改动导致 viewBox↔渲染尺寸不成比例时的 letterbox 隐患（当前 w-full h-auto 下等比，none 为无操作兜底）。

### Bug 2 修法

- 读数条各段定宽化：时间 `.padStart(14)`、O/H/L/C 各 `.padStart(11)`、涨跌 `.padStart(14)`、V `.padStart(8)`，数值右对齐定长；容器加 `tabular-nums`（font-mono 下为双保险）。任意蜡烛切换时各段字符数恒定，整行渲染宽度恒定。`truncate` 保留兜底。

### 验证结果

- `npx tsc --noEmit` 通过。
- 吸附逻辑改为纯数据坐标最近邻，与渲染缩放解耦；读数条定长后宽度不随内容变化。

### 遗留

- 同第一轮遗留；读数条定长值按当前 tickSize/价格量级设定，若未来价格位数显著增长需同步调整 padStart 宽度。

## 十七、Bug 修复记录：落盘 jsonl 删除重建后回放游标失效（2026-09-03）

### 根因

`src/app/api/options/intraday/route.ts` 的回放游标（key=日期|产品|scope）只按 `size < offset` 判截断。当日 jsonl 被**删除重建**（同名文件从头重写）后，新文件 size（~1.7MB）仍大于旧 offset（~700KB），于是从新文件的旧偏移处继续增量读，解析到错位行，该 key 的 bars/levels 只剩稀疏残段（实测 d90 坏、0dte 正常——取决于各 key 建立时的偏移）。

### 修法

游标条目新增文件身份锚点 `firstCapturedAt`（全量读时记录的首行 `capturedAt`，即当日第一轮快照时间戳，文件被替换必然变化）：

- 增量读前校验：仅当 `mtimeMs` 与缓存不同（采集追加/替换都会改 mtime，正常轮询 mtime 不变零额外 I/O）且 `offset > 0` 时，`readFirstCapturedAt`（readline 只读首行，流截断在 64KB）比对，不符即游标作废全量重读。
- `size < state.offset` 原截断判断保留。
- 文件不存在时该日期 key 从 `replayCache` 删除（下次全量/空态）。

### 验证

- `npx tsc --noEmit` 通过。
- 重启 dev（清掉进程内坏缓存）后实测 `GET /api/options/intraday?product=ES&scope=0dte|d90`：两 scope 完全一致（bars=800、levels=1、首末 unix 相同）；对照当日 jsonl 实有 3 轮、仅末轮含 ES（前两轮该产品缺失按设计跳过），levels=1 为正确全量结果。

## 二十、迭代执行记录 · 第十二轮：主周期判定改为固定优先级（0D·CW 丢牌修复）（2026-09-03）

用户实测反馈：NQ、scopes=0DTE+90D+全部 时，`0D·CW 29,150` 横线画出来了但右轴没有它的徽标，同屏 90+ALL·CW / 90+ALL·FLIP / SPOT / 0D·FLIP / 0D+90+ALL·PW 牌都在。纯前端 `src/features/board/IntradayPanel.tsx`，接口不动。

### 根因

与最初怀疑的 claimed 聚类 / 垂直推开 / y 域判断均无关（用当轮真实值逐步推演 + 浏览器 DOM 取证排除：tickSize=0.25，各价位差最小 40 点，推开循环只改 y 不删牌，0D·CW 在 y 域内部未 clamp）。

真实根因：**主周期判定用的是 `scopes[0]`（点击追加顺序）**。该窗配置实际为 `["all","0dte","d90"]`（窗口创建于全局"全部"档，后补选 0DTE/90D 追加在尾部），于是 `segments` 里 `all` 是主周期（`primary: i === 0`）。后果链：

- `0dte-CW@29150` 合并组不含主周期成员 → `primary=false`，且 short=CW≠FLIP → 被徽标构建的"纯非主周期组只出 FLIP 牌"规则跳过 → 丢牌；
- 同屏"正常"的牌恰好都是含 `all` 成员的组（90+ALL·CW、90+ALL·FLIP、0D+90+ALL·PW）或主周期自己的 all·SPOT / 纯非主周期但豁免的 0D·FLIP——所以唯独 0D·CW 消失；
- SPOT 横线/徽标也错挂在 `all` 上（`all-SPOT`），y 域跟随的也是 all 的墙。

### 修法

主周期不再按点击顺序取 `scopes[0]`，改为按固定优先级 `SCOPE_MERGE_ORDER`（0DTE > 90D > 全部 > 收盘）取**选中项里优先级最高者**：

- `segments` 的 `primary` 改为 `scope === primaryScope`；`primary` 段引用从 `segments[0]` 改为 `segments.find(s => s.primary)`（迁移轨迹/y 域跟随随之归位到 0DTE）。

### 三层通道架构（为高频数据铺路，本次全部实现）

按变化频率分三层，各走各的通道：

1. **数据层（分钟级，未来秒级）——版本化 + 派生缓存**：采集数据进 store 带单调版本号（现用 capturedAt，未来 WS 推送换 seq，接口不变）；派生计算（profile 聚合、徽标模型）走 selector + memo（key=版本号）；**latest-wins 帧合并**——数据多次到达只设脏标记，rAF 消费时取最新、中间帧丢弃，渲染压力恒定。
2. **几何层（人为频率，pan/zoom 每帧）——旁路通道 + 脏检查**：06 发布 {domainMin, domainMax, plotTop} 走 zustand transient subscribe（不触发 React 渲染）；08 rAF 消费，脏检查未变则跳过，变了 DOM 直改 SVG transform，绕过 reconcile。
3. **渲染层——结构归 React，位置归命令式**：08 VP 的结构（条数/宽度/颜色）由 React 渲染（仅数据版本变化时重建）；所有条的 y 位置挂在统一 `<g transform>` 上由第二层 rAF 直改。

脉冲动画挂数据版本号触发，与渲染解耦。未来接高频源唯一改动点 = 采集写入端（REST 轮询 → WS 推送），三层以下不动。

### 性能口径

- 数据频率 1 分钟：数据层每分钟最多重算一次；几何层只随鼠标动；两者互不放大。
- 未来秒级/tick 级：帧合并保证 UI 每帧最多应用一次新版本；08 VP 渲染体约百级 SVG 元素，单帧 <1ms。

### 根因（两个叠加）

   依然没装 → 实测尺寸恒 {0,0} → 永远停在首帧骨架（无 svg 的空壳）→ 全黑空图。

2. **次生 bug（修复过程中实测暴露）**：VP rAF tick 里 `svg.setAttribute("viewBox", …)` 在
   脏检查（`g.dataset.vpKey === key → return`）之后；实测宽从兜底 100 变为真实值（如 110）时

   补写 → viewBox 高卡死在 1，y 向内容被拉伸数百倍。另 GexVpPanel 合并 ref 初版用内联函数，

### 修法

- `use-measure-size.ts` 重写：**回调 ref + `useEffect(deps [node])`**——被测元素任何时刻挂载

- **塌 0 保持上一次有效尺寸**：update 时跳过 0×0 读数（窗口瞬隐/布局抖动不误伤），

### 优化点清单与前后机制

1. **mousemove（十字光标/VP 光标）rAF 合帧**（最大头）。
   - 前：每个 mousemove 事件直接 `setHover`/`setVpHover` → 整棵组件树（含蜡烛+量柱 2N 节点、徽标、VP）每事件全量重渲染，且每事件一次 `getBoundingClientRect`。
   - 后：事件只把 `{clientX, clientY}` 写 `hoverEventRef`，rAF 回调里经 `applyHoverRef`（渲染期赋值的最新闭包，同 viewRef 模式）执行原逻辑，一帧最多一次渲染、一次 rect 测量。hover 是纯跟随无累积状态，一帧内中间事件结果被最后事件覆盖，数学等价。`onMouseLeave` 取消挂起 rAF 防止离场后光标被 setState 回写。
2. **wheel 缩放：事件队列 + rAF 本地 replay**。
   - 前：每个 wheel 事件两次 setState（触控板惯性滚动一帧多事件 → 多次渲染）；每事件一次 rect 测量。
   - 后：事件入 `wheelQueueRef`，rAF flush 内用本地 `{lSpan, lEnd}` 逐事件 replay（初值从 viewRef 反推：`span=null ⟺ vSpan≥total`、`endIdx=null ⟺ vEnd≥total`，反推完备），最后一次性 setSpan/setEndIdx。与原"事件间渲染、下次读新 viewRef"的复利推进数学完全一致；锚点 frac 仍按各事件 clientX 逐个计算；rect 一帧一次。原生 `addEventListener("wheel", …, {passive:false})` 沿用（第二十一轮已修，无 React passive 警告问题）。
3. **拖拽平移 mousemove rAF 合帧**。
   - 前：window mousemove 每事件 setEndIdx + 每事件 `rect0(el)` 测量。
   - 后：存最新 clientX，rAF 内执行原逻辑；pan 用 mousedown 时 panRef 快照起点算绝对位移，取最后事件与逐事件结果相同（等价）；测量降到每帧一次。`onUp` 取消挂起 rAF。
4. **静态大子树拆 memo 组件**（渲染分层）。
   - `CandleLayer`（蜡烛+影线）、`VolumeLayer`（分隔线+量柱）从主组件渲染体抽出并 `memo()`，props 全部原始值 + `agg` 引用（useMemo 稳定）——hover 交互帧浅比较全等，整层 2N 节点跳过重建。几何映射（x/y/volY）、涨跌配色、z 序位置逐行保持原口径。`VpStrip` 外包 `memo()`（props = model 引用 + 原始几何值，交互帧稳定）。
   - 未把派生计算改 useMemo 链：三个早退 return 在前，hooks 不能放其后；memo 组件内 `agg.slice(vStart, vEnd)` 只在可视窗口/数据变化时重跑，已覆盖大头。
5. **卸载清理**：新增兜底 effect 卸载时取消全部挂起 rAF（hover/wheel/pan），防卸载后 setState。

## 三十七、迭代执行记录 · 第三十四轮：拆开两种右侧重叠 + 像素级 overlay 让位（2026-09-04）

### 调研结论（两种覆盖不是同一件事）

第三十三轮把 gutter 改成悬浮轴 + `RIGHT_MARGIN_BARS=5` 之后，放大/缩小会露出两套不同的遮挡：

1. **放大 K 线后的「gutter 盖住 K 线」**：5 根 bar 的时间域右 margin 随缩放变宽。15 根可见时最后一根蜡烛只在映射区间约 72% 处，右侧 ~28% 是空区；刻度/SPOT 的 `--ms-plot-bg` 衬底叠在这块空区上，看起来像旧 gutter 列还在把 K 线「切掉」。这是 **bar 单位空区 + 刻度衬底**，不是徽标牌。
2. **缩小 K 线后的徽标压 K 线**：同一套 5 根 bar 在全视野下只剩几个像素（800 根时约 0.6% 宽）。CW/PW/FLIP chip 是固定像素宽（常规 ~104px，三周期合并 ~129px，上限 170px）、不透明 `--ms-panel-bg`。空区不够时牌直接压在最右几根蜡烛上。这是 **徽标 overlay**。

不能靠「再加大 RIGHT_MARGIN_BARS」修问题 2：缩小后 bar 很窄，加到 20 根也只有十几 px；放大后空区会更大，问题 1 更糟。

正确交互：K 线向左让的是 **overlay 实测像素宽**（随牌内容变，不随缩放变），不是更多根 bar。
