# 周期架构（Gamma 周期分层）迭代开发文档

> 创建：2026-09-02
> 范围：**看板级 scope 架构改造**——影响 05/06/08/09/10 等所有消费共享分析层的面板，非单面板迭代
> 背景：gamma 的含义随周期分层（0DTE 日内钉扎 / 90D 波段墙 / 全期限结构仓位 / 收盘仓位真值锚点），看板的周期选择器要从现在的 `0DTE | 近月 | 全部` 升级为四层架构。

## 一、周期档定义（已拍板；2026-09-03 十一轮起五档，见十一节）

| 层 | 按钮 | 聚合范围 | 数据源 | 刷新 | 状态 |
|---|---|---|---|---|---|
| 收盘固定 | `收盘` | 全期限所有 serie | Go `/options/dashboard?scope=close`（结算价 + 收盘 OI） | 每天一次，全天冻结 | 后端 `state: partial`，面板保持空态 |
| 0DTE | `0DTE` | 当日到期 serie | Go `/options/dashboard?scope=0dte` | **60 秒**（实测） | 已实装 |
| 30DTE | `30DTE` | DTE ≤ 30 的全部 serie（**含 0DTE**） | Go（原生 scope `d30`） | **300 秒**（实测） | 已实装（2026-09-03 新增） |
| 90D | `90D` | DTE ≤ 90 的全部 serie（**含 0DTE**，嵌套口径：0DTE ⊂ 30DTE ⊂ 90D ⊂ 全部） | Go（原生 scope `d90`） | **300 秒**（实测） | 已实装（替代旧"近月"档） |
| 全部 | `RTH`（key 仍 `all`） | 所有 serie | Go（原生 scope `all`） | **300 秒**（实测） | 已实装；显示名 RTH |

**"收盘固定"与"RTH（全期限盘中）"的关系**：聚合范围相同（全期限），差别在数据时点——收盘固定 = 每天一次的结算真值（仓位锚点，全天不变）；RTH = 盘中最新价/IV 重估的浮动值。两者偏离本身是交易信号。
**收盘固定层的形态**：五档语境下为第一档（`收盘`），整体切换看板（不叠加参考线；叠加层列入 06 后续计划，见六节）。

## 二、架构改造点

### 1. scope 语义升级（服务端聚合口径；现由 Go 侧实现）

- 现有 scope 枚举 `0dte / nearest / all` 升级为五档 `close / 0dte / d30 / d90 / all`（`nearest` 已由 `d90`/`d30` 替代）。
- **删除 `nearest`（近月），新增 `d90`**：serie 选择从"最近一条"改为"DTE ≤ 90 的全部 serie 聚合"（聚合走服务端 combine 路径，与"全部"同法、只是 serie 子集不同）。
- `close`：数据源未完整发布，scope 接受该值但返回**空态标记**（`has_data: false` 或等效），所有面板按"无数据不降级"红线显示空态，不报错、不造数。
- 影响面：05/08/09/10/06 全部经服务端聚合结果消费 scope，切换语义随之一致变化，无需逐面板改口径。**05 面板本体不动**（用户既定），只是它显示的"90D"内容随 scope 变化，后续再做期限矩阵对齐（六节）。

### 2. 切换器 UI（BoardView 级）

- 顶部 scope 切换按钮组 `0DTE | 近月 | 全部` → `收盘 | 0DTE | 30DTE | 90D | RTH` 五档多选总控（至少 1 个，[0] 为主周期）。本节为早期设计稿，最终以第十一节多选总控为准。
- `收盘` 档在 Databento 接入前：按钮可选中，各面板显示"收盘数据待接入（Databento EOD）"空态；按钮旁可加小注记。
- `0DTE` 档：按钮 title/图例注记"快照周期 60 秒（实测）"。

### 3. 收盘固定层数据落地（未来，先定契约）

- 后端每日 EOD 拉取 → 结算价 + 收盘 OI 跑一次全期限核算 → 由 Go 侧出 `scope=close` 快照（本仓只消费）。
- 面板切 `收盘` 档时读该快照，全天不变；快照缺失 → 空态。
- 本仓只定义消费契约与空态行为，不承担取数实现。

### 4. 刷新频率分层（已由后端实现）

OI 每天只变一次，各层对刷新的需求完全不同：

| 层 | 需求 | 实测 |
|---|---|---|
| 收盘 | 每天一次（EOD） | 每日一次 |
| 0DTE | 高频 | **60 秒** |
| 30DTE / 90D / 全部 | 低频足够（盘中重算只是价格重估） | **300 秒** |

后端已按此分层出快照；本仓不再涉及任何采集环节。

## 三、服务器负荷与增量架构（设计约束，所有后续迭代遵守）

核心原则：**原始数据只追加、只读一次；昂贵计算分层缓存；任何请求触发全量重算都是 bug。**

| 负荷点 | 对策 | 状态 |
|---|---|---|
| 大响应重复拉取（levels 3.4MB / dashboard d90 ~900KB） | 服务端按快照版本缓存；前端脏更新，版本不变不重复请求 | 见 `本地侧优化方案.md` L1/L4 |
| 聚合结果重复计算 | 由后端随快照预计算，前端零计算 | 已落实 |
| 上游存储增长 | 由后端治理（本仓不落任何行情数据） | 不适用本仓 |
| 并发请求阻塞 | 同 key 请求合并 + 进程内缓存 + 并发闸门 | 部分落地，见 L4/L6 |
