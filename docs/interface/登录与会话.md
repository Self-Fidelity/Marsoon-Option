# 登录与会话

Main 沿用 Rust 客户端的邮箱验证码登录：

1. `POST /api/auth/otp` 接收邮箱，由 Next 服务端转发到 Go `POST /auth/otp`。
2. `POST /api/auth/verify` 接收邮箱和验证码，由 Next 服务端转发到 Go `POST /auth/verify`。
3. Go 返回 Supabase access token、refresh token 和用户信息；Next 将令牌写入 `HttpOnly`、`SameSite=Lax` Cookie，浏览器脚本不能读取令牌。
4. Next 另写入 HMAC 签名的短期会话 Cookie。`src/proxy.ts` 用它保护页面和 `/api/options/*`，未登录页面跳转到 `/login?next=...`，未登录数据请求返回 401。
5. `/api/auth/session` 在会话临近过期时使用 refresh token 静默续期，并通过 Go `GET /auth/session` 校验仍有效的 access token。应用运行期间每 4 分钟检查一次会话。
6. `POST /api/auth/logout` 清除全部登录 Cookie。

登录成功和已有有效会话访问 `/login` 时使用浏览器级 `location.replace` 进入目标页，确保首次受保护页面请求携带刚写入的 Cookie，避免客户端 `replace` 与 `refresh` 竞态导致登录页持续停在会话检查状态。

## 受保护入口

- `/`、`/board`、`/teaching`
- `/gamma`、`/flow`、`/volatility`、`/zero-dte`
- `/panel-shot`
- `/api/options/*`

`/login` 和 `/api/auth/*` 保持公开，否则用户无法登录或续期。

## 环境变量

- `OPTIONS_API_BASE_URL`：Go 服务地址，默认本机 `http://127.0.0.1:8000`。
- `AUTH_SESSION_SECRET`：会话 Cookie 的 HMAC 密钥。生产环境必须设置为独立的高强度随机值；开发环境未设置时使用仅限本机开发的固定回退值。

## 用户留存上报（2026-09-09）

- 复用 `marsoon-rs` 网页端语义：OTP 登录成功进入应用或冷启动恢复 Session 后上报一次；页面从后台恢复且距上次成功超过 30 分钟时再上报。
- 全局 `ClientActivityReporter` 住在 `AppShell`，`enabled` 在受保护页面间保持 true；普通路由切换、组件渲染和 Token 刷新不会创建新事件。
- 浏览器先调用 `/api/auth/session` 续期近过期 Token，再向同源 `/api/auth/activity` 只发送幂等 `event_id`。Next BFF 从 HttpOnly Cookie 读取 access token，并代理 Go `/client/activity`。
- BFF 固定填充 `platform=web`、当前 package version、`device_id_hash=null`、`metadata={app: options}`；不接受浏览器传 user id、邮箱、日期、服务器时间或 Token。
- pending event UUID 在网络请求前写入 localStorage，失败后 30 秒或恢复联网时复用；同时保存 pending user id，登录用户变化即丢弃旧事件。
- 成功响应（包括 RPC 判定 duplicate/throttled/daily_limit 的 2xx）清除 pending 并记录 `marsoon.last-activity-at`；服务端继续执行 30 秒限流和每日上限。

验证码、access token 和 refresh token 不写入 localStorage，不返回给客户端 JavaScript，也不进入 URL。
