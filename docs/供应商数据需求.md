# 期权数据需求规格（提交供应商）

> 我们在开发一个**实时期权看板**，数据粒度为 **1 分钟快照**。
> 本文档列出需要供应商提供的数据项、字段口径、覆盖范围与质量要求。
> 交付方式不限（REST / WebSocket / 数据库直写均可），字段口径以本文为准。

> **内部状态注记（2026-09-02，不对外）**：开发期已用 Barchart 免费延迟源覆盖本文 P0-1（K线）、P0-2（链逐档 bid/ask/volume/OI，部分月份有官方 Greeks）的大部分内容；免费源为延迟 ≥15 分钟数据且禁止商用，正式实时仍按本文档向供应商提需求。当前免费源的已知缺口：levels 历史序列、Pin Risk、全期限成交量分布。

## 1. 标的产品

| 代码 | 标的 | 乘数（USD/点） | 最小变动 |
|---|---|---|---|
| ES | CME E-mini S&P 500 期货期权 | 50 | 0.25 |
| NQ | CME E-mini Nasdaq 100 期货期权 | 20 | 0.25 |
| GC | COMEX Gold 期货期权 | 100 | 0.10 |

三个品种均为**期货期权**（标的为期货合约，非指数现货）。所有价格类字段以标的期货价格口径为准。

## 2. 通用约定（所有数据项适用）

- **时间戳**：Unix 秒，UTC。区间参数为左闭右开 `[from, to)`。
- **快照粒度**：1 分钟。快照内需注明数据覆盖的实际时间窗（如 `observed_min_unix` / `observed_max_unix`），因为同一快照内不同行权价的最新成交时间可能不同，我们要据此区分"新鲜/混合/过期"。
- **缺失语义**：无数据的字段返回 `null` 或不返回该字段，**严禁用 0 填充**。缺失与"真实值为 0"必须可区分。
- **质量标记**：每行带 `quality_flags` 位掩码（位掩码，非枚举），请提供位定义文档（如：1=插值、2=过期、4=盘口交叉……具体位含义由供应商定义，需在文档中列明）。
- **方向约定（重要）**：所有 Put 侧的方向性指标（如 put GEX、put delta）**自带负号**交付，我方不再反号。net = call + put。
- **Unknown 方向成交量**：计入总量，但不计入任何方向性拆分。
- **OI 是快照值**：不可跨分钟累加。
- **补数机制**：盘中断档后恢复时，需要能区分"补发的历史快照"与"实时快照"（可用时间戳判断即可，无需额外字段）。

## 3. 需求明细（按我方优先级排序）

### P0-1 标的期货 K线（1 分钟 OHLCV）

**用途**：日内面板主图，叠加期权墙位水平线。只要简单 K线，**不要 tick、逐笔、盘口深度**——存储与性能考虑，明确不需要深度数据。

- 品种：ES / NQ / GC 期货（主力连续或与期权希腊字母计算所用标的价格**同源同口径**的合约序列，二者必须能对齐到同一价格轴）
- 粒度：1 分钟 OHLCV
- 范围：当日盘中实时 + 至少近 5 个交易日历史回看
- 频率：每分钟更新（允许盘后低频）

字段（每根 bar）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `unix` | int | bar 起始时间（Unix 秒，UTC） |
| `open` / `high` / `low` / `close` | float | 该分钟开高低收 |
| `volume` | int | 该分钟成交量（手） |

无成交分钟的处理方式请说明（返回空 bar 标记或不返回该分钟均可，但需明确，前端不假设序列连续）。

建议接口形态（可议）：

```http
GET /options/underlying-bars?product=ES&timeframe=60&from=<unix>&to=<unix>
```

### P0-2 期权链逐档字段增强（行权价 × 到期 维度）

**用途**：期权链下钻面板。我方面板以"行权价 × 到期日"网格消费数据，需要在每个网格点上补充以下字段：

| 字段 | 类型 | 必需性 | 说明 |
|---|---|---|---|
| `call_volume` / `put_volume` | int | **必需** | 该档该分钟（或快照窗口）成交量 |
| `call_delta` / `put_delta` | float | 可选 | 若提供：注明定价模型（如 Black-76）、所用波动率与利率口径；put delta 自带负号。若不提供，我方自行计算 |
| `call_bid` / `call_ask` / `put_bid` / `put_ask` | float | 可选 | 快照时刻最优买卖价；缺失按 §2 缺失语义处理 |

- 覆盖范围：全部上市到期（含 0DTE）× 现货上下各不少于 ±10% 的行权价带
- 频率：1 分钟快照

### P0-3 全期限成交量分布（按到期范围过滤）

**用途**：成交量 PCR / BCR 面板。现有 0DTE 成交量分布接口的口径保留，但需要**推广到全部到期**：

- 维度：行权价 × 到期日 × Call/Put × 成交方向（Buy / Sell / Unknown）
- 过滤：支持按到期范围查询（当日到期 / 最近到期 / 全部）
- 方向拆分规则请说明（按主动方判定：成交价贴 ask 记 Buy、贴 bid 记 Sell、无法判定记 Unknown——若贵司规则不同，以贵司文档为准，但需明确给出）
- 频率：1 分钟快照；当日累计值可接受（注明是分钟增量还是累计）

### P1-1 Pin Risk / Max Pain（到期 pinning 相关指标）

**用途**：到期日面板增强。需要供应商**正式计算并交付**的字段（我方前端不自造公式）：

- Max Pain 价位（按 OI 计算，注明算法口径）
- Pin Risk 相关度量（如到期日 ATM 附近 OI 集中度，具体口径可协商）

优先级低于 P0 三项，可与 P0 分批交付。

### P2-1 资金流与墙迁移事件（扩展项）

- 资金流：按分钟的净 delta 名义金额（`net_delta_notional`）及当日累计值
- 墙迁移事件：Call Wall / Put Wall / Gamma Flip 价位发生迁移的事件点（时间、指标、旧值、新值）

属于后续扩展，现阶段仅需评估可行性与报价。

## 4. 我方已消费的字段口径（供整体报价参考）

以下字段我方看板已在展示（当前为演示数据），正式接入时同样由供应商真实数据提供。**如贵司行情源可直接产出，请一并报价**；若只提供原始链数据（OI/成交/IV/标的价格），我方自行批计算，则无需报价。

以"单快照总览"为例，核心字段：

- 标的价格、regime 标记、net/gross GEX
- Call Wall / Put Wall / Gamma Flip / Key Gamma Strike
- Expected Move 上下界、ATM IV、可见窗口 Put/Call OI 比、0DTE GEX 占比
- 分到期聚合：OI、GEX、ATM IV、Expected Move、Delta、Charm
- 行权价 × 到期网格：call/put GEX、call/put OI、call/put IV
- 时间序列：上述关键价位的 1 分钟迁移序列（回看 60 分钟）

> 若供应商交付的是原始数据而非衍生指标，需保证：OI 与成交量按行权价×到期齐全、IV 或期权价格可得、标的价格同口径——我方可据此自行计算 GEX 系列指标（Black-76）。

## 5. 验收标准

每项数据交付时，按以下逐条验收：

1. 字段齐全性：§3 对应条目字段表内"必需"字段全部存在，命名与类型一致（或提供映射表）。
2. 缺失语义：抽查无成交档位/分钟，确认无 0 填充。
3. 方向约定：抽查深虚值 Put 档，确认 put 侧方向性指标为负值。
4. 时间一致性：快照时间戳单调、`observed` 窗口合理（同快照内最大时间差可说明）。
5. 连续性：盘中时段连续 30 分钟无断档（断档需提供补数说明）。
6. 口径文档：quality_flags 位定义、方向拆分规则、定价模型（若提供 Greeks）三项文档齐备。
