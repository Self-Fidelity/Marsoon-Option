## 1. 现状：数据从哪来

> **2026-09-10 更新**：数据源为 **Go 期权服务（Databento → ClickHouse）**，且是**唯一**来源。

**当前唯一在跑的链路**：Go 服务（后端响应 `source: "databento-go"`、`model_version: "black76-oi-flow-v4"`）→ Next.js BFF `/api/options/*` → 面板。BFF 唯一模式直连 Go（`OPTIONS_API_MODE`/legacy 本地组合层已于 2026-09-11 删除），所有读接口全部走 Go，BFF 只做代理、字段归一化、空态与错误清洗。

**本仓不再持有任何本地数据源**：旧的免费网页采集链路（采集脚本、快照内存仓、本地分析/Greeks 模块、采集推送与状态路由、状态徽标组件）已于 2026-09-10 **彻底删除**，代码与文档零残留。数据新鲜度改由 Go 派生的 `GET /api/options/version`（仅 `(product, scope, unix)`）驱动。

**完整接口清单、字段结构与实测数据见 [`../interface/Go后端接口清单.md`](../interface/Go后端接口清单.md)**（12 个接口，含鉴权域与 WebSocket）。本文 §2 只保留面板视角的速查。

分层不变，接数据源不动图表组件：

```
API Response → TS api types → ViewModel → TanStack Query → 展示组件
```

- 产品：NQ / ES / GC（期货期权，乘数 20/50/100，tick 0.25/0.25/0.1）
- 范围：scope = `close / 0dte / d30 / d90 / all`（close=收盘固定层空位，Databento EOD 待接入；旧值 nearest 已删除；all 显示名 RTH），状态同步 URL
- 时间约定：Unix 秒；`from/to` 为 `[from, to)`；levels timeframe=60s（**1 分钟快照**）、回看 60 分钟 = 60 个桶

## 3. 口径红线（来自上游 README，必须遵守）

- `put_gex` 已带负号：`net_gex = call_gex + put_gex`，**不得重复反号**。
- Unknown 成交量计入总量，但不进方向 Delta。
- OI 是快照，不能跨分钟累加。
- `quality_flags` 是位掩码，不是枚举。
- Wall / Gamma Flip / IV 缺失时**不绘制**，不能降级为 0。
- Heatmap 各 strike 可能来自不同时间，不是原子快照（看 `observed_min/max_unix`，处理 mixed/stale）。
- 后端没给的指标（IV Rank、Max Pain、ΔOI、25Δ Skew、VRP、Pinning）**隐藏或显示 `--`，前端不得自造公式**。

## 5. Intraday 的 K线决策（已闭合，2026-09-02）

**只要简单 K线，不要深度数据**——不存 tick、不存逐笔、不存盘口，省存储也省性能。

- 粒度：**1 分钟 OHLCV**（与快照对齐，方便叠加；前端显示可聚合为 5m/15m）。期货近 24h 约 1500 根/品种/天，三个品种一天数千行，存储仍可忽略。
- **数据源已落实**：Go 后端 `/options/underlying-bars`（2026-09-10 实测 200）。本仓不再自行采集 K 线。
- 用法（即截图形态）：K线为主图，把 dashboard.summary 的 `call_wall / put_wall / gamma_flip` 画成三条水平线（CW 用 Positive 青绿、PW 用 Negative 红、Flip 用 Brand 金——色值按 `业务逻辑.md` §5 的 Marsoon 主题映射），价格触碰墙位一目了然。
- 注意区分：**K线只描述价格行为**；「GEX 曲线日内演变」由 levels 序列承担。面板叙事"曲线是记录不是预测"对应这两个数据的分工。

**该接口已由 Go 后端实现**（2026-09-10 实测 200），`数据开发` 不再需要 bars1m 随快照推送：

```http
GET /options/underlying-bars?product=NQ&underlying=NQU6&timeframe=60&from=<unix>&to=<unix>
```

```ts
interface UnderlyingBarsResponse {
  product: string;
  underlying_symbol: string;
  timeframe: number;                 // 秒，60
  from: number; to: number;
  has_data: boolean;
  source: string;
  bars: { unix: number; open: number; high: number; low: number; close: number; volume: number; final: boolean }[];
}
```

前端 `/api/options/intraday?bars_only=true` 走的就是它（06 面板先画 K 线的快路径，不等期权计算）。

## 7. 与我们工程的对接

- 上游的 `OptionProduct/OptionScope/StrikeHeatmapCell/...` 类型就是我们 `技术架构.md` §5 数据契约的现实来源：迁移时以 `src/api/options.ts` 为底本，`ChainSnapshot` 由 dashboard 的 cells + summary 组装，`GexLandmarks` 直接取 summary 的 walls/flip。
- 看板**实时接后端**：TanStack Query hooks 指向同源 `/api/options/*`，由 BFF 代理到 Go `/options/*`；盘中按各 hook 自定间隔轮询，BFF 侧另有 10s 进程内缓存去重。
- **已无 demo 回退**：拿不到数据就走空态 + `missing_reason`（由 Go 裁决），不再生成 `local-demo`；legacy 本地合成分支已于 2026-09-11 随 `OPTIONS_API_MODE` 一并删除。
- **失效驱动**：前端"数据版本变化即失效"机制（`features/options/data-freshness.ts`）30s 轮询 Go 派生的 `/api/options/version`（仅 `(product, scope, unix)`），版本号变化才失效活跃查询；若存在 error 查询则每次轮询重试一次（防首屏失败后永久空态）。
- 本地开发联调：`pnpm dev`（Node 20.9+ / pnpm 11+，默认 4173 端口）；提交前 `pnpm lint && pnpm build`。
