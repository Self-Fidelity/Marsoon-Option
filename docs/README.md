## 维护约定

1. **单一真源**：同一件事只在一处定义，其他文档只引用不复制。
   - 接口事实 → `interface/Go后端接口清单.md`
   - 口径红线 → `architecture/数据开发.md` §3
   - 视觉约束 → `frontend/UI视觉规范.md` §1
   - 数据契约 → `architecture/技术架构.md` §5
2. **面板文档两分**：规格（意图/契约/边界）与迭代记录（逐轮过程/常量）分开维护，规格末尾放「口径索引」指向记录中的具体轮次。
3. **新增文档**：先判断归属哪一大类 → 放进对应子目录 → 回到本文件登记一行（管什么 + 什么时候改它）。
4. **跨文档引用**：用相对路径 —— 同目录直接写文件名，跨目录用 `../`；不要用绝对路径。
5. **状态标注**：文档顶部用一行注明「创建日期 / 状态（定稿 | 方案待实施 | 已实施 | 已失效留档）」；失效内容不要静默删除，标注留档并指向 git 历史。

**边界原则**：两层之间只允许通过「数据契约」（`architecture/技术架构.md` §5）交互。
面板组件（业务）不关心数据从哪来；数据层（技术）不关心图怎么画。
