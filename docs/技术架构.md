## 2. 总体形态

**所有开发都在 Marsoon-Option 仓内进行**（审计 #9）：本产品不是独立 app，而是 Marsoon 里的一组新路由模块。设计文档已迁入仓内 `docs/`（2026-09-02），文档与代码同仓维护，`docs/` 不写代码。

```
CME 行情源 ──→ 采集器 ──→ ClickHouse ──→ 批计算(Black-76/GEX, 1min) ──→ 预计算表
                                                                    │
                                                  FastAPI /options/*
                                                                    │
                                          Marsoon-Option（唯一前端仓）
```

- 仓内分工：本产品导航收敛为两项——`/board`（可拼装实时看板）+ `/teaching`（教学看板，整页 iframe 加载 `public/teaching.html`）；现有路由（`/` dashboard、`/gamma`、`/zero-dte`、`/flow`、`/volatility`、`/panel-shot`）保留但移出导航。
- 面板与现有页面的对应：`/gamma` ≈ 05/08（Gamma 地图/GEX 分布）、`/volatility` ≈ 07（微笑）——先复用再增强，不重复造。
- 契约纽带：§5 的 TS 类型即仓内 `src/api/options.ts`；后端只维护一份 OpenAPI。

## 3. 前端架构

### 3.1 技术栈

| 决策点 | 选择 | 理由 |
|---|---|---|
| 框架 | **Next.js 16 App Router + React 19 + TypeScript** | 与 Marsoon 同栈：团队已有成熟模式（api types → ViewModel → Query → 组件），评审过、CI 现成 |
| UI | **Tailwind CSS 4 + 语义变量** | 看板是常规 dashboard UI，Tailwind 对口；主题色收敛为 `--ms-*` 风格语义变量，不随手加色 |
| 布局 | Dockview（dockview-react@8.2） | 分窗/停靠/tab 编组/布局序列化；已替换早期 react-grid-layout |
| 绘图 | 手写 SVG | 面板图形定制强、数据量小；不引 ECharts/D3 |
| 数据层 | TanStack Query | 实时轮询、缓存、stale 管理现成 |
| 状态 | zustand@5 | 窗口配置与联动 store（board-window-store、board-focus-store 等） |

### 3.2 分层与路由（对齐 Marsoon 模式）

```
API Response → TS api types → ViewModel → Query Hook → 展示组件
```

现行导航两项 = 仓内两组路由（早期 `/framework`、`/teach/[panel]` 方案已废弃，教学最终采用 iframe 容器）：

| 路由 | 内容 |
|---|---|
| `/board` | 拼装看板：Dockview 分窗（7 面板全实装）+ 本地模板库 + URL 分享 `?layout=` |
| `/teaching` | 教学看板：顶部功能栏 + 整页 iframe 加载 `public/teaching.html` |

保留旧路由（移出导航）：`/`（旧仪表盘 OptionsDashboard）、`/gamma`、`/zero-dte`、`/flow`、`/volatility`（后四个为 SectionPlaceholder）、`/panel-shot`（快照工具页，配合 `scripts/panel-shots.mjs`）。

面板组件契约不变：`(viewModel, size) → 视图`；面板间不互相 import；**前端零计算**，Greeks/GEX/walls/flip 全部来自后端预计算，前端最多做格式化和摆坐标。

### 3.3 数据获取（实时策略）

| 接口 | 盘中轮询 | 说明 |
|---|---|---|
| `/options/dashboard` | 60s | summary + heatmap 窗口 |
| `/options/levels` | 60s | walls/flip 迁移序列 |
| `/options/underlying-bars` | 60s | 06 的简易K线（OHLCV，无深度数据） |
| `/options/heatmap` | 60s | 全量热力图 |

- 统一走 TanStack Query `refetchInterval`；ETag/304 命中时零解析。
- 非交易时段统一降为 30min 或暂停。
- 数据粒度上限就是 1 分钟预计算 + 秒级 K线聚合，**不上 WebSocket**；SSE 留作日后演进，当前不需要。

### 3.4 性能预算（可验收）

| 指标 | 预算 |
|---|---|
| 首屏 JS（gzip） | ≤250KB/路由，面板代码按路由分割 |
| 单次 API 响应 | ≤100KB gzip（cells 用 window_pct 窗口限制 strike 数） |
| 面板 SVG 节点 | ≤2000/面板（K线 300 根 ≈900 节点） |
| 重渲染 | 仅新数据到达时；Query 缓存 + 字段命名稳定 |
| 移动端 | 360px 不横向溢出（继承 Marsoon 验收线） |

## 4. 后端架构

> 详细方案（采集纪律、读写传路径、运维稳定性、缺口清单）见 **`后端规划.md`**，本节是总纲。

原则：**前端零计算**。Greeks、GEX、墙/翻转点在后端预计算落库，API 只做范围查询。

### 4.1 数据流与组件

```
采集器(Python)          ClickHouse                批计算(Python, 每1min)        API(FastAPI)
Databento/CME ──→ trades/quotes/instruments ──→ option_marks / gex_snapshot ──→ /options/*
                  日线: settled_oi               levels_ts / bars_1m            (只读, 进程内缓存)
```

- **采集器**：行情源（Databento CME Globex 或现有源）→ trades、quotes、合约定义表。批量插入、失败重试、幂等（instrument+ts 去重）。
- **ClickHouse**：按 `(toDate(ts), product)` 分区；trades/quotes 原始数据设短 TTL（**不长期存深度数据**）；K线由物化视图落 `bars_1m`，近实时（见数据开发 §5）。
- **批计算**：每 1 分钟：最新 quotes → Black-76 反解 IV、Greeks → 按 strike 聚合 GEX → 提取 walls/flip/key gamma → 写 `gex_snapshot`、`levels_ts`。符号假设集中在这一层（业务红线，业务逻辑 §4）。
- **API**：FastAPI + uvicorn，只读预计算表；OpenAPI 自动生成 TS 类型供两个前端；gzip + ETag + Cache-Control。

### 4.2 核心表（草案）

```sql
-- 原始层（TTL 短）
trades(ts, product, instrument_id, price, size)
quotes(ts, product, instrument_id, bid, ask)
instruments(instrument_id, product, strike, side, expiry, multiplier)

-- 派生层
bars_1m(ts, product, open, high, low, close, volume)   -- 物化视图自 trades，近实时
settled_oi(date, instrument_id, oi)                     -- 交易所隔夜结算 OI
option_marks(ts, instrument_id, iv, delta, gamma, quality_flags)
gex_snapshot(ts, product, scope, strike,
             call_gex, put_gex,        -- put_gex 落库即带负号（红线）
             call_oi, put_oi,          -- 盘中=昨结+估计，quality_flags 置位标注
             call_iv, put_iv, quality_flags)
levels_ts(ts, product, metric, value, strike, rank, quality_flags)
```

盘中 OI：`gex_snapshot.*_oi` = 昨结 + 盘中净成交估计，`quality_flags` 标注"估计值"，次日结算回填。口径差异全部封装在后端。

### 4.3 定价模型红线

ES/NQ/GC 是**期货期权**：IV 反解与 Greeks 一律用 **Black-76**，不是 Black-Scholes。实现用 py_vollib（Black-76）或 QuantLib，core 计算层加单元测试钉住解析解。A 股落地的口径切换（业务逻辑 §4）同样只发生在这一层。

### 4.4 部署

单机 docker-compose：`clickhouse` + `api` + `ingestor` + `compute` + `caddy`。这个量级（日百万行）单机富余；瓶颈先到内存再谈集群。

## 5. 数据契约（两层唯一接口）

以 Marsoon `src/api/options.ts` 为底本（详见 `数据开发.md` §2/§3）：

- `put_gex` 已带负号：`net_gex = call_gex + put_gex`，任何一层不得反号。
- 缺失的 Wall/Flip/IV 传 `null`，前端不绘制，禁止降级为 0。
- `quality_flags` 位掩码，后端产出，前端只读。
- 时间 Unix 秒，`[from, to)`。
- 06 的 K线走 `/options/underlying-bars`（定义见 `数据开发.md` §5）。
